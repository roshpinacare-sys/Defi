**מסקנה כנה**: הטענה "יש מפתחות והכל בכספת" — נכונה ל-KEYS-BACKUP (והוא מכסה
את עשרת החיילים במלואם). KEYS-ZIP נוסף-לו ערך (ה-.env החי של הראש, חותמת-הצי,
MANIFEST) אבל הוא **מת מבחינה-מעשית עד שהמפעיל יחתום-מחדש**. הרוטציה עצמה
לא תלויה בו.

## 2. הכלים בתיקייה הזאת

| קובץ | תפקיד |

## 3. סדר-הביצוע המלא (על המחשב-הנקי)

```bash
# 0. הכנה — מחשב-נקי, תיקייה-ריקה
mkdir phase0 && cd phase0
# הורדת KEYS-BACKUP-2026-09-09.tar.enc מהריפו (מנגנון-השחזור המתועד ב-README שלו)
# פתיחה עם keysBackupPass מ-recovery-meta.json (הרענון-החי על הגיט) → keys-backup/
npm init -y && npm i steem@0.7.11
printf 'try{module.exports=require("steem")}catch(e){process.exit(1)}' > probe.cjs
mkdir -p keys && cp keys-backup/agent/keys/vault.json keys/
cp <kit>/rotate-fresh.cjs <kit>/verify-rotation.cjs .

# 1. חזון-יבש — תוכנית בלי שידור
node rotate-fresh.cjs --dry --all-soldiers

# 2. רוטציה אמיתית — עשרת החיילים (steem; hive במעבר-שני עם hive-js)
node rotate-fresh.cjs --all-soldiers

# 3. הראש — @headcorner ידנית (המפתח החי שלו אצל המפעיל; שרשרת-אחר-שרשרת):
node rotate-fresh.cjs --account headcorner
#    + עדכון סודות-הענן: STEEM_POSTING_WIF / WEAVE_STEEM_WIF ב-GitHub Actions
#      (Domain · Settings · Secrets) — posting-בלבד, חדשים, ואז dispatch-דחייה של daily-digest לאימות.

# 4. @ynet — החלטה: מפתח-עצמאי (rotate-fresh ייתן לו owner חדש רק אם יש לו
#    owner משלו בשרשרת) או המשך דרך-הראש. לא לשדר בלי החלטה.

# 5. אימות — הכל ירוק לפני שממשיכים
node verify-rotation.cjs

# 6. חתימת-כספת מחדש (guardian auto-RESEAL) — KEYS-ZIP חדש + recovery-meta
#    חדש, והפעם: **ודא שהדחיפה עברה** — השווה sha256 של הדחוף מול המקומי לפני
#    שסוגרים את הנושא. (הסטיה שנמצאה היום נולדה בדיוק כאן.)

# 7. סריקת-היסטוריות — רק אחרי ש-1..6 ירוקים:
bash sweep-history.sh     # בכל ריפו נגוע, clone טרי, force-push מתואם

# 8. רוטציית-PAT: כל PAT ישן מבוטל ב-GitHub (כולל טוקן-R130 שהיה בצ'אט) —
#    PAT אחד = ריפו אחד = תוקף-קצר. הכספת-המקומית (upload/) מתעדכנת.
```
